Scripts to copy updated authoritative artifacts from the tdwg/bdq/ tree into the tdwg/bdq/_review directory to run build scripts and for the submission of the standard for review.

WARNING: All files listed in the copy_files.sh script MUST NOT be edited in their destination files in the _review directory.  Current authoritative and maintained copies live elsewhere.  See the file lists below.

**copy_files.sh** Copies authoritative files from outside the _review tree into their target locations in the _review tree. It no longer builds the RDF representations of the Tests: since 2026-11-14 `dist/bdqtest.*` is generated from rs.tdwg.org by `export_rs_baseline.py`.

**do_build.sh** Executes the python scripts in `_build_review/` to build artifacts from the templates, configuration files, and vocabulary documents in the `_build_review/` tree.

The do_build.sh script which runs the python scripts to populate /tg2/_review/ is itself invoked in the workflow defined in .github/workflow/pages.yml which uses the script and assets in /_site_resources/ to build the website and deploy to GitHub Pages, which the /CNAME file identifies as bdq.tdwg.org.  **Note that the copy_files.sh script is not invoked in the workflow, so the files copied by copy_files.sh must be updated manually before running the build scripts and before submission for review.**

Third party Python libraries required by the python scripts:
```
pandas
pyyaml
rdflib
```

No third party application is required by the build. kurator-ffdq ([kurator-org/kurator-ffdq](https://github.com/kurator-org/kurator-ffdq)) can still produce draft RDF of proposed Tests from a term-version CSV; see the commented instructions in copy_files.sh.

To build _review, run the following commands in the bdq/tg2/_make_review directory:

```bash
python3 export_rs_baseline.py   # only when rs.tdwg.org has changed; then review and commit the export
copy_files.sh
do_build.sh
```

**draft_build.sh** *(2026-11-16)* builds the documents and `dist/` from a proposed change: a release under test, processed but not committed, in a local rs.tdwg.org checkout. Run it on a branch, never on `master`, and do not merge the result: `./draft_build.sh <rs.tdwg.org checkout> <release date>`. It runs `export_rs_baseline.py --rs <checkout> --worktree`, `copy_files.sh`, `do_build.sh` with `BDQ_RS_SOURCE=<checkout>`, and **mark_draft.py**, which inserts a notice in every generated document that it is a draft, not issued, and that versions dated on the release under test are proposed. See `tg2/maintenance/README.md`, "Proposing changes".

The builders read rs.tdwg.org (document metadata and versions, term list metadata) from the source given by the environment variable `BDQ_RS_SOURCE`: a branch, tag, or commit of tdwg/rs.tdwg.org on GitHub (default `bdq`), or the path of a local checkout.

**export_rs_baseline.py** regenerates this repository's copies of the BDQ vocabularies from rs.tdwg.org, the source of truth (`deployment_rs_tdwg_org.md`, Section 13.1, the baseline export): the term-version files in `tg2/_review/vocabulary/`, the ontology (`tg2/_review/dist/bdqffdq.owl`, `tg2/_review/dist/bdqffdq.*`, generated by rs.tdwg.org's `process/build_ontology.py`) and the `bdqffdq` term list alone (`tg2/_review/dist/bdqffdq_terms.*`), the Test graphs (`tg2/_review/dist/bdqtest.*`), and the GUID tables in `tg2/core/`. It reads one commit of tdwg/rs.tdwg.org (default: branch `bdq` from GitHub; `--rs <checkout> --ref <ref>` for a local checkout) and records it in `tg2/_make_review/rs_tdwg_org_baseline.json`. `--check` reports which files differ from rs.tdwg.org without writing them. Requires rdflib.

# Structure of source and target directories for the build.

## Source files for the bdqtest vocabulary

** CORE tests are no longer maintained from the markdown tables in the github issues.** 

**As of 2026-11-13 the source of truth for the Tests, and for all BDQ vocabularies, is tdwg/rs.tdwg.org, branch `bdq-source`** (see [Where the BDQ standard is maintained](../README.md#where-the-bdq-standard-is-maintained-sources-of-truth)). `tg2/_review/vocabulary/bdqtest_term_versions.csv` (from which `copy_files.sh` derives `tg2/core/TG2_tests.csv` and `tg2/core/TG2_multirecord_measure_tests.csv`), the other term-version files, the ontology, and the GUID tables are generated from rs.tdwg.org by **export_rs_baseline.py** (below).
