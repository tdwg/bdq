## Where the BDQ standard is maintained: sources of truth

As of 2026-11-13, during the public review ([#340](https://github.com/tdwg/bdq/issues/340); plan: [`_make_review/deployment_rs_tdwg_org.md`](_make_review/deployment_rs_tdwg_org.md)):

| What | Source of truth: make changes here | Copies and generated files: do not edit |
|---|---|---|
| The terms of all seven vocabularies (`bdqdim`, `bdqenh`, `bdqcrit`, `bdquc`, `bdqval`, `bdqffdq` and its axioms, `bdqtest`), their versions, and the GUID tables behind the Test graphs | [tdwg/rs.tdwg.org](https://github.com/tdwg/rs.tdwg.org), branch `bdq-source`, `process/bdq-revisions/`: a new release directory per change (see its [README](https://github.com/tdwg/rs.tdwg.org/blob/bdq-source/process/bdq-revisions/README.md)), processed onto branch `bdq`, served at [bdq-public-review.rs.tdwg.org](https://bdq-public-review.rs.tdwg.org/) | `_review/vocabulary/*_term_versions.csv` and `core/` (`TG2_tests.csv`, the GUID tables): copies that the build here still reads; until the build reads rs.tdwg.org, a change made in rs.tdwg.org must be copied into them by hand. `_review/vocabulary/bdqffdq.owl` and `_review/dist/`: generated |
| Document metadata: titles, abstracts, authors and contributors with their roles, licence, dates, versions | rs.tdwg.org, branch `bdq-source`: the `documents` of the release `config.yaml` | `_build_review/templates/*/document_configuration.yaml` and `_build_review/authors_configuration.yaml`: fallbacks for the build, used only for documents or values rs.tdwg.org does not have |
| Document content: the text of the guides, the supplement, the tutorial, the landing page, and the headers and footers of all documents | here, `_build_review/templates/` | `_review/`: generated by `_make_review/do_build.sh` |
| Build code | here, `_build_review/`, `_make_review/`, and `/_site_resources/` | |

Never edit files in `_review/` directly, apart from `_review/README.md`.

## Outcomes

TG2 has been working for over 10 years to evaluate, refine and develop new tests that evaluate 'data quality'/'fitness for use' of biodiversity coded using the Darwin Core Standard. TG2 has developed a framework for describing, running and evaluating a standard suite of tests, test data and comprehensive vocabularies.

We acknowledge the use of tests in use by

* The Atlas of Living Australia (ALA)
* The Global Biodiversity Information Facility (GBIF)
* iDigBio
* Ocean Biogeographic Information Facility (OBIS)
* Centro de Referência em Informação Ambiental (CRIA)
* Biodiversity Information Serving Our Nation (BISON)
* Vertnet
